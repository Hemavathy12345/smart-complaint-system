Smart Campus Complaint Management - Application Flow

1. The browser requests the application page from the Express server at http://localhost:3000.
2. Express serves the HTML, CSS, and JavaScript files from the public directory.
3. When a user signs in or registers, the frontend sends a JSON request to the authentication API.
4. The backend validates the request, checks or creates the user in MongoDB, and returns a JSON Web Token (JWT).
5. The frontend keeps the token in browser local storage and sends it with later API requests in the Authorization header.
6. The backend verifies the token and checks the user's role before allowing protected actions.
7. Students can submit complaints and retrieve their own complaints. Administrators can view and filter complaints, update statuses, add notes, and delete complaints.
8. The backend uses Mongoose to read and write users and complaints in MongoDB, then returns JSON responses for the frontend to display.

The frontend and API are served from the same Express application. The browser communicates with the API over HTTP using routes such as /api/auth/login and /api/complaints. The browser never connects directly to MongoDB.
